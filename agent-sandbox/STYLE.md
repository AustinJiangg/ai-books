# 凡例

本书讨论的对象变化很快，许多数字只有一个来源，不少说法彼此冲突。为了让读者能分辨"论文说的""厂商说的""本书算的"和"本书猜的"，全书在标题、数字、出处、图表和交叉引用上遵守同一套约定。附录 A（术语表）开头的"用词规范"是本凡例的细则，二者不一致时以附录 A 为准；数字以附录 B 为准。

## 一、结构与标题层级

1. 全书分七部分、28 章，另有附录 A–E。部分标题用中文序数（第一部分……第七部分）。
2. 章标题写作"第 N 章　标题"，章号后用全角空格。节写作"N.M　标题"，小节写作"N.M.K　标题"，均用全角空格隔开编号与标题。小节以下不再编号，用段首加粗短语提示层次。
3. 每章有四个不编号的固定栏目："本章导读"在章首，"本章小结""本章数字溯源""参考文献"依次在章末。
4. 边栏用引用块排出，首行写"**边栏：类别——标题**"。类别只有三种："谱系"（系统之间的人员与代码渊源）、"方法"（读数字、做测量的方法）、"延伸阅读"。边栏是补充，跳过它不影响正文论证。
5. 标为"本书建议"的段落或引用块，是本书提出的做法，见第五节。

## 二、术语

1. 术语首次出现时写作"中文（English）"，例如"放置引擎（placement engine）"。此后只用固定译名。全书译名以附录 A 为准。
2. 下列英文词在正文中保留不译，首次出现时加中文注，每章只注一次：
   - **Agent**：引用中国标准、政策文件时用"智能体"。
   - **rollout**：首次注"（一次策略与环境交互直至结束的完整采样过程，也称轨迹展开）"，其产物称"轨迹"。
   - **harness**：首次注"（外壳/评测框架，负责驱动 Agent 循环、工具与打分）"。scaffold 译作"脚手架"。
   - **microVM**：首次注"（微虚拟机）"。full VM 译作"完整虚拟机"，简称"完整 VM"。
   - **reward hacking**：首次注"（奖励投机，指模型以非预期途径拿到奖励）"。specification gaming 译作"规约博弈"。
3. 以下词有固定译法：
   - egress 译"出站"，ingress 译"入站"。"出网"只出现在引语或口语转述中。
   - allowlist 译"白名单"，denylist 译"黑名单"，default-deny 译"默认拒绝"。
   - overcommit 译"超售"。
   - prompt injection 译"提示注入"。
   - confused deputy 译"混淆代理人"。
   - lethal trifecta 译"致命三要素"。
4. 公司、产品、项目名一律不译，如 DSec、AgentENV、OpenEnv、Harbor。代码标识符同样不译，并用行内代码格式，如 `memory.reclaim`、`network_rules`。
5. 计数单位要分清："个沙箱"指一个被隔离的执行实例，"个环境"指 RL 或评测意义上的任务世界，二者不互换。"运行时"须写明是"沙箱运行时"（runc、gVisor、Firecracker 等隔离技术栈），还是"沙箱内运行时"（沙箱内部执行命令的守护进程）。
6. 全书反复使用以下框架性名称，写法固定：
   - **三场景**：训练、评测、产品推理。"产品推理"不省作"推理场景"。
   - **两类对手**：被利用的代理人；作为对手的模型。
   - **八层架构**：①接入与 API、②控制面、③节点运行时、④镜像与存储、⑤状态管理、⑥密度与资源、⑦网络与出站、⑧RL 集成与完整性。引用时写"第④层（镜像与存储）"。
   - **Agent 负载五特征**：突发、稀疏、有状态、低扇出、可中断。DSec 原文另有"异构""执行不可信"两项，合称七特征。
   - **三种产品范式**：一次性短命容器；任务级临时 VM 或容器；有状态长期 VM。
   - **状态三层**：本地快照与 fork；外部副作用事务；回滚语义与安全。
   - **reward hacking 二分**：取回型与篡改型。取回型又分沙箱内取回与出站取回。
   - 状态操作用词（快照、检查点、恢复、暂停、休眠、fork、回滚）的区分见附录 A 用词规范第 3 节。

## 三、数字格式

1. 一律用阿拉伯数字。四位及以上的数加千分位逗号，如 3,200、380,000、51,219,741。年份、版本号、编号、代码中的数值不加。
2. 原文用 K、M、k 等缩写的，首次出现时保留原文写法，并在括注中给出完整数值或说明，如"约 38 万（摘要称超过 380,000；§2.4 作 ∼380K）"。
3. 数字与单位、量词之间空半角空格，如 35 分钟、160 个节点、1.5 TB、256 KiB。百分号紧贴数字，如 40.2%。范围用短横"–"连接，如 4.2%–13.3%、30–35 分钟。
4. 倍数在正文中写"倍"，表格中可写"×"。
5. "约""超过""至少""最多""up to"等限定词照原文保留，不省略，也不加强。原文写"峰值"的不改写为"平均"，写"观测到"的不改写为"上限"。
6. 日期在括注和表格中写作 YYYY-MM-DD，正文叙述中也可写"2026 年 9 月"。来源后注"2026-10-04 读取"，指本书抓取该网页的日期，不是网页的发布日期。仓库材料注明提交号与日期，如"HEAD e02976a（2026-09-30）"。同一提交的作者日期与提交日期不同时，两者都写明。

## 四、出处与来源类型

1. 关键数字首次出现时，在括注中写明出处与来源类型，如"（DSec §4.2，表 2；论文自述）"。同一段内重复出现的数字不再重复标注。DSec 论文按节、表、图引用，如"（DSec §6.4）""（DSec 表 1）""（DSec 图 10）"。其他论文同样写节号，如"（RollArt §3.1）"。
2. 来源类型固定为下列五类：
   - **论文自述**：论文或技术报告中作者对自身系统的陈述。
   - **一手文档**：当事方的官方文档、博客、仓库、标准文本，或当事方的事故复盘。
   - **厂商自报**：厂商官网、文档中的性能与规模宣称，以及营销文、客户案例，均未经独立测试。
   - **二手报道**：媒体、社区、竞品、聚合博客、Wikipedia 与第三方逆向材料。
   - **笔者推算**：由书中已引用的数字算出，括注写明算式，如"（笔者推算：13.5 ÷ 295）"。
3. 另有一个补充类型**二手引述**：一手文件存在，但本书只能经第三方转引原句（例如 PDF 抓取被截断）。它与"二手报道"的区别在于，引的是当事方原句，不是第三方自己的叙述。
4. "论文自述"与"厂商自报"不等于事实，只说明话是谁说的。来源可信度为中、低的数字，正文写明"据××自报""据××报道"及日期。
5. 原文引语给中文译文并加引号；关键句首次出现时，在括注中附英文原文。正文中的其他来源写短名，如"AgentENV README""TechNode"，完整条目与 URL 列在章末"参考文献"，以 [n] 编号。

## 五、冲突、空白、推断与本书建议

1. **冲突并列。**来源互相矛盾时，正文并列各方说法，写明各自的来源与日期，不替读者二选一。附录 B"冲突数字登记"（C-xx）给出每条冲突的判断和建议措辞，正文照此书写。
2. **"未披露"是结论。**某项信息在本书检索范围内没有公开来源时，写"未披露"，表格中可写"未披露（已查：……）"，不用推测填补。附录 C 写作"文档未见（10-05）"，意思是截至 2026-10-05，本书读过的一手材料中没有相关接口或说明；它不等于该系统没有这项能力。
3. **不应引用的说法。**附录 B"不应引用的数字"（X-xx）列出流传较广、但已被一手来源纠正的说法。正文如需提及，只把它作为"被纠正的说法"出现。
4. **推断。**本书由已引用事实推出、原文没有明说的结论，句末标"（推断）"，必要时写明依据，如"（推断，基于本书检索范围）"。
5. **本书建议。**本书提出的设计、测量方法、规格字段和条款，标"本书建议"或"（本书建议）"。它们没有经过工业实践验证，与"某系统已经这样做"严格区分。

## 六、谱系与固定句式

1. 凡提及 TrEnv → AgentENV → DSec 这条作者谱系，一律注"（推断，基于作者重合）"。这是本书据作者名单与代码提交作出的推断，不是当事方的陈述。
2. DSec 与 AgentENV 的关系只用一个固定句式："DSec 的 microVM 存储路径使用了 AgentENV 仓库中开源的 Rust OverlayBD/ublk 组件（论文称'我们参与贡献'）"。全书不写"DSec 基于 AgentENV""DSec 是 AgentENV 的生产版"一类说法。
3. 谱系与提交史的细节只在第 24、25 章展开，其他章用一两句概述并交叉引用。

## 七、图表与交叉引用

1. 图、表各自按在本章出现的先后顺序编号，如图 24-1、表 24-1。
2. 表题放在表上，图题放在图下，均加粗，写作"**表 N-M　标题**""**图 N-M　标题**"，编号与标题之间用全角空格。
3. 示意图在图题后注明依据，如"（示意图，依据 DSec §6.1 绘制）"；含推断的示意图同时注"推断"。表注放在表下，以"注："开头。
4. 每章的"本章数字溯源"表至少列出数字、含义、来源（含原文位置）、类型，以及对应的附录 B 编号。部分章另设"核对"一列，记录本书是否回原文复核。
5. 交叉引用写作"（见第 11 章）""（见 24.3.4 节）""（见表 24-4）""（见图 19-1）"。节号前不加"第"。引附录 B 时可直接写编号，如"（附录 B B24-04）""（C-01）""（X-06）"。

## 八、附录的用法

- **附录 A　术语表**：开头的"用词规范"规定译名、计数单位与框架性名称，是本凡例第二节的细则。其后按主题分为 A–I 九组，每条给出定义、易混淆项和首次出现的章。遇到不熟悉的术语时，先查这里。
- **附录 B　关键数字溯源表**：全书数字的最终依据。按章分区，编号写作 Bnn-xx，附录 C 的专用数字编号写作 BC-xx。每行列出原文数字、口径、来源、来源类型、日期、可信度、冲突备注与使用章节。另有"冲突数字登记"（C-xx）和"不应引用的数字"（X-xx）两节。正文与附录 B 不一致时，以附录 B 为准。
- **附录 C　各系统 API 对照**：把 15 个沙箱系统的接口名按生命周期、网络与凭据、训练场景缺失概念三张表并列，接口名原样照录。它是 2026 年 10 月初的切片，引用时以所注的提交号与读取日期为准。
- **附录 D　负载刻画模板**：以第 3 章表 3-6 为底稿，给出 48 个字段的填写模板，以及 DSec、Kimi K3/AgentENV、快手与 RollArt 三份示例。空格写"未披露"。读者可以用它报告自己系统的负载，也可以用它判断一份公开数据缺了什么。
- **附录 E　文献库**：全书引用的文献，每条只登记一次，放在主章节下，其他相关章节列入"另见"。核实状态分五档：一手已核实、仅摘要或二手、背景知识未核实、存在冲突、无法访问。引用"仅摘要或二手"及以下各档的条目时，应回到原文。
