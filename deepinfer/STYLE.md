# 写作规约

本文件是《DeepInfer 技术手册》全书的体例、术语与质量规约。为了使各章节具备统一的学术严谨度与工程实用价值，所有章节的编写与审校均须严格对照本文件执行。

---

## 一、本书定位与读者画像

本书是一部系统解析 **DeepInfer**（[deepseek-ai/DeepInfer](https://github.com/deepseek-ai/DeepInfer)，代码基线为 commit `9bd9cf2`）的计算机系统工程教材与技术内幕手册。

DeepInfer 是支撑 DeepSeek 大规模云端生产环境（如 DeepSeek-V4.1-Flash）的核心高性能推理框架，单集群日服务规模达 155 万亿 token，在低谷电价下实现了每卡时 38 美元的商业收益。本书深入剖析该框架如何通过底层算子协同设计、零开销异步调度、有界重放注意力、动态推测验证与跨节点专家负载均衡，实现超高吞吐与极低时延。

- **对标质量**：顶级计算机系统学术专著与工业级架构白皮书。
- **目标读者**：具备操作系统、并行计算、计算机体系结构与分布式系统基础的研究生、大模型推理系统研发工程师及云基础设施架构师。
- **知识假设**：读者了解 Transformer 基本原理、CUDA 编程与分布式通信（NCCL/MPI），但无需提前掌握 YOCO、MHC、Engram 或 DeepEP 的具体细节。全书按需引入预备机制。

### 五条质量红线

1. **论断必有依据**：凡涉及框架内部机制、调度逻辑或内存排布的陈述，必须指明确切的代码文件路径及类/函数名（如 `csrc/engine/scheduler.hpp` 中的 `Scheduler::_schedule()`）。代码中未明确体现、基于工程经验推断的部分，必须显式标注「推论：」。
2. **问题先于方案**：任何算法设计或优化原语登场前，必须首先剖析朴素实现的技术瓶颈与硬件瓶颈（如访存墙、CPU 发射气泡、尾部延迟或通信阻塞）。
3. **收益必谈代价**：严禁宣传口吻。介绍优化机制时，必须成对分析其吞吐/时延收益与带来的显存占用、调度复杂度、数值精度损耗或实现约束。
4. **代码引用精确规范**：正文中的代码路径一律使用相对于 DeepInfer 仓库根目录的相对路径，严禁包含任何本机或构建临时目录（如不得出现 `.src/`），严禁包含绝对行号（行号易随版本漂移，应指明函数名或结构体定义）。
5. **配图严谨高效**：图表服务于核心机制的理解。流程图/时序图用于并发与调度流程，架构图用于模块与边界划分，ASCII 布局图用于内存/字节结构。

## 二、基线版本与称谓口径

全书统一采用以下基线版本与固定称谓：

| 称谓 | 指代对象 | 源码位置 / 备注 |
|---|---|---|
| **DeepInfer** | DeepSeek 开源推理框架（主分支 commit `9bd9cf2`，2026-10） | 仓库主干代码 |
| **DeepSeek-V4 / V4.1-Flash** | 目标推理模型架构，采用 CED/YOCO、MHC、MLA 与 MoE 结构 | 默认权重模型基线 |
| **ZOS** | Zero-Overhead Scheduler，零开销异步批调度器 | `csrc/engine/zos.cpp` 及相关 TileLang 算子 |
| **EPLB** | Expert-Parallel Load Balancing，专家并行负载均衡组件 | `deepinfer/model_executor/eplb/` |
| **TileLang** | DeepSeek 领域专用可定制高性能算子编程语言与编译器 | 算子实现层 |
| **DeepEP** | DeepSeek 开源的高性能 MoE 通信库（专家并行 All-to-All） | `vendor/DeepEP/` |
| **DeepGEMM** | DeepSeek 自研针对低精度矩阵乘法的 FP8/FP4 GEMM 库 | `vendor/DeepGEMM/` |
| **FlashMLA** | 针对 DeepSeek 多头潜在注意力（MLA）高度优化的注意力算子 | `vendor/FlashMLA/` |
| **3FS** | 专为大规模大模型集群设计的分布式键值与文件存储系统 | 生产集群部署环境 |

## 三、术语对照表（固定中英文表达）

正文以中文阐述；代码符号、命令行指令、环境变量与底层数据结构字段保留原始英文。术语首次出现时注明英文全称，同一章节内保持统一：

| 中文术语 | 英文术语 | 含义与规范 |
|---|---|---|
| 预填充 / 提示词阶段 | Prefill / Prompt | 生成首个 token 的初始前向计算阶段 |
| 解码阶段 | Decode / Completion | 自回归逐 token 生成阶段 |
| 首字延迟 | TTFT (Time to First Token) | 预填充阶段完成并返回首 token 的端到端耗时 |
| 词元生成间隔 | TBT (Time Between Tokens) | 解码阶段每生成一个 token 的时间间隔 |
| 专家并行 | EP (Expert Parallelism) | MoE 架构中各专家分布在不同加速卡上的并行策略 |
| 数据并行 | DP (Data Parallelism) | 请求在多卡或多副本间独立分发的并行模式 |
| 上下文并行 | CP (Context Parallelism) | 针对超长上下文单请求沿序列维度切分的并行模式 |
| 多头潜在注意力 | MLA (Multi-Head Latent Attention) | 采用低秩投影视角压缩 KV 缓存的高效注意力机制 |
| 单次缓存架构 | YOCO (You Only Cache Once) | 仅在 Encoder 层缓存完整全局 KV 的跨层设计 |
| 滑动窗口注意力 | SWA (Sliding Window Attention) | 局部受限窗口注意力，结合有界重放恢复精度 |
| 多头超连接 | MHC (Multi-Head Hyper-Connections) | 扩展残差流维度的多通道残差混合连接结构 |
| 多词元预测 | MTP (Multi-Token Prediction) | 预测后续多个 draft token 的辅助推测头结构 |
| 零开销调度 | ZOS (Zero-Overhead Scheduling) | CPU 调度规划与 GPU 前向执行完全异步重叠的设计 |
| 对称内存 | Symmetric Memory (`symm_mem`) | NVLink 互联域内跨卡直接访问的统一虚拟地址空间 |
| 分块缓存管理 | Paged KV Cache / BlockManager | 类似于虚存分页的固定大小物理 KV 块分配系统 |
| 结构化输出 | Structured Outputs (SO) | 约束模型输出严格匹配 JSON/正则/文法的自动机引导机制 |

## 四、文档结构与排版规范

每一篇正文文档结构严格统一为以下骨架：

```markdown
# NN · 章节标题

> 一到三句精炼题注，概括本章探讨的核心问题与系统收益。
> **前置知识**：相关的先修章节或系统概念。
> **源码指引**：本章剖析的核心源文件相对路径与类/函数名。

## 0. 本篇要回答的问题

以 2~4 个具体的工程设问展开，直指核心矛盾。

## 1. 业务痛点与设计挑战

剖析传统机制在此场景下的瓶颈（访存开销、CPU 气泡、通信竞争等）。

## 2. 核心架构与数据结构

结合 ASCII 内存图、状态转换图或结构体定义，阐明该机制的原语与内部表示。

## 3. 算法实现与代码执行流

跟踪代码具体调用链，逐级展示核心分支逻辑与算子调度。

## 4. 关键设计取舍与边界代价

收益与代价成对列出（时延、显存、吞吐、兼容性约束）。

## 5. 小结

提炼 3~5 条核心技术结论。

## 延伸阅读 / 下一篇

指向后续章节或外部技术文献。
```
