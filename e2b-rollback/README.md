# E2B 沙箱快照回滚从零讲透

一本写给计算机新手的书，讲一套实际在用的“沙箱级”快照回滚：在 E2B 与 Firecracker 上，给一台**正在运行**的沙箱存档，过一会儿再把**同一台**沙箱原地变回那一刻。

- **代码**：[AustinJiangg/e2b-infra](https://github.com/AustinJiangg/e2b-infra) 仓库里的 `0001-adapted-for-arm-architecture.patch`（orchestrator 一侧）、`firecracker.arm`（带三处扩展的 Firecracker）和 SDK 覆盖层。
- **机器**：鲲鹏 ARM 服务器，HDBSS 硬件脏页跟踪在鲲鹏 950 上；存档盘是 ext4。
- **范围**：原理、设计、实现、性能、优化、测试，以及往后怎么改。

全书围绕三件事展开：**回得对**（内存、CPU、设备、磁盘回到同一个时刻，拿不准就报错）、**回得快**（代价只看改了多少、回退多远，不看虚机多大）、**讲得清**（多快、对不对、坏了怎么办，都拿得出证据）。

前 4 篇打地基：要解决什么问题；一台沙箱的“现场”由哪七项组成；页、脏页、位图、稀疏文件、reflink 这些基础；为什么不直接用 E2B 原生的 pause / resume，定下了哪些原则。

之后分四部分：

1. **怎么做**：请求怎么被宿主截下；一次存档、一次读档逐步走；脏页怎么记、HDBSS 怎么开；内存差分树和回滚集；磁盘封存只改名；Firecracker 里的九个阶段；网络、设备与时间；失败分级与不变量；并发、生命周期与空间。
2. **和原生快照一起用**：两种快照的分工，原生 pause 的精确增量，以及存过档的沙箱再做原生 pause 时怎么不漏页。
3. **多快**：怎么量、量出了什么、从单沙箱到并发长跑做过哪些优化。
4. **对不对、往后怎么走**：测试怎么证明回得对；全景、排障、已知问题和后续方向。

约 7.4 万汉字，20 篇，62 张图。

本书只读不练，没有需要动手的实验；文中的代码和命令都是帮助理解的示例片段，不逐函数讲源码。部署、网络、存储的细节只讲到本书用得到的程度，详见《E2B 部署从零讲透》《E2B 沙箱网络从零讲透》《E2B 沙箱存储从零讲透》。

## 阅读建议

- **完全的新手**：从头顺着读。第 2、3 篇是概念基础，后面大量用到。
- **熟悉虚拟机和内存管理**：可以跳过第 2、3 篇，从第 4 篇开始。
- **只想抓主线**：读第 1、4、5、6、7、9、11、13 篇。
- **第 9 篇是全书的核心**：差分树、回滚集和它的证明，读懂它，其他篇章都是围绕它的展开。
- **只关心数字**：读第 16、17 篇；想知道数字是怎么一步步降下来的，读第 18 篇。
- **要接手改代码**：先读第 7 篇末尾的八条顺序约束、第 12 篇末尾的检查表、第 13 篇的不变量清单，再读第 20 篇。
- 每篇末尾有“本篇小结”表格，复习时过一遍小结即可。

## 几个容易出乎意料的事实

| 事实 | 篇 |
|---|---|
| 沙箱里没有任何程序监听 49984 端口，存档请求在进沙箱之前就被宿主截下了 | 5 |
| 读档不新起虚拟机，在同一个 Firecracker 进程里原地写回，进程、网卡、磁盘设备都不重建 | 2、11 |
| 存档盘是 ext4，没有 reflink，所以内存不能“每代复制一份”，只能“只存差分、按页往祖先找” | 3、9 |
| 磁盘存档存下来的层，就是客户机自己写出来的那个写层文件，只改了个名字 | 10 |
| 读档的代价只和“当前离目标有多远”有关，和目标存档本身多大、历史多长都无关 | 7、9 |
| 写快照成功之后，后面再失败就不能“删掉了事”：那份差分是那段脏页的唯一记录 | 6、13 |
| 读档后单调时钟会倒退；墙钟在读档返回前被校回现在 | 12 |
| 把存档目录整个拷走，也恢复不了 | 14 |
| 删掉当前所在的那个存档，几乎腾不出空间；要删最旧的 | 14 |
| “只留最近 N 个”的用法，没有合并就会让磁盘无限增长 | 9、18 |
| HDBSS 必须在所有 vCPU 创建之后启用，顺序错了不报错，一条脏页都记不到 | 8 |
| 一次 Go 垃圾回收的长停顿，根源是另一个线程睡在内核的内存回收里 | 18 |
| 同一个测试脚本，换了一版 SDK，从 59 项全过变成 57 项全过，两次都打印“全部通过” | 19 |
