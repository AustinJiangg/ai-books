# 第 3 篇｜网络基础（二）：以太网、ARP、路由表与转发

> **本篇目标**：搞清楚一个包是怎么“一站一站”往前走的。读完本篇，你会知道：MAC 地址和 IP 地址各管什么；ARP 是怎么从 IP 查到 MAC 的；路由表怎么决定下一站；一台机器什么时候会帮别人转发包。最后你会明白：为什么同一个网段里两台机器用同一个 IP 会出大乱子。这是第 10 篇的伏笔。

---

## 一、两层地址：收件人和中转员

### 1.1 一个快递的比喻

你从北京寄一个包裹到广州。面单上写的是**最终收件人**：广州某街某号。但包裹不会直接飞过去，它会经过好几站：北京分拣中心 → 武汉中转站 → 广州分拣中心 → 派送员 → 收件人。

每一站，快递员只关心一件事：**下一站交给谁**。他不需要知道整条路线，只要看面单上的目的地，查一下“去广州的件交给哪辆车”。

网络通信一模一样，而且有**两层地址**：

- **IP 地址**像面单上的最终收件人，从起点到终点**基本不变**。
- **MAC 地址**像“这一段路交给哪个中转员”，**每过一站就换一次**。

### 1.2 MAC 地址

MAC 地址是网卡的“硬件地址”，48 位，写成 6 段十六进制：

```
02:fc:00:00:00:05
```

物理网卡出厂时就烧好了一个全球唯一的 MAC 地址。虚拟网卡的 MAC 地址则由软件指定。

MAC 地址只在**同一段网线（同一个二层网络）**上有意义。一个包从一台机器发到直接相连的另一台机器，靠的就是 MAC 地址。

在 E2B 里，每个沙箱客户机的网卡 MAC 都是 `02:FC:00:00:00:05`。全都一样。这在普通网络里是不可想象的，第 10 篇会解释 E2B 为什么敢这么做。

---

## 二、以太网帧：信封套信封

### 2.1 帧的结构

数据在网线上传输的基本单位叫**以太网帧**（frame）。它像一个信封：

```
┌──────────────── 以太网帧 ──────────────────────────────────────────┐
│ 目的 MAC │ 源 MAC │ 类型 │ ┌────────── IP 包 ───────────────────┐ │
│          │        │0x0800│ │ 源 IP │ 目的 IP │ 协议 │ ┌─ TCP/UDP ─┐│ │
│          │        │      │ │       │         │      │ │ 端口+数据 ││ │
│          │        │      │ │       │         │      │ └───────────┘│ │
│          │        │      │ └────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────┘
```

一层套一层：

- 最外层是以太网帧头，写着这一段的源 MAC 和目的 MAC。
- 里面是 IP 包，写着最终的源 IP 和目的 IP。
- 再里面是 TCP 或 UDP，写着端口号（第 4 篇）。
- 最里面才是真正的数据。

每经过一站（路由器），外层的以太网帧头会被**拆掉重写**，换成下一段的 MAC 地址；里面的 IP 包一般原样往下传。后面要讲的 **NAT** 是个例外：它会改写 IP 包里的地址。

### 2.2 tap 设备收发的就是帧

先埋个伏笔：Firecracker 虚拟机通过 **tap 设备**和宿主机交换数据，交换的正是这种完整的以太网帧，带 MAC 地址的那种（第 6、9 篇）。所以虚拟机的网卡看起来就像接了一根真网线。

---

## 三、ARP：知道 IP，问 MAC

### 3.1 问题

一台机器要给同一网段里的另一台机器发包，它知道对方的 **IP**，比如 `169.254.0.22`。可是填以太网帧头需要对方的 **MAC**。从哪知道？

### 3.2 喊一嗓子

答案是 **ARP**（地址解析协议）。做法非常朴素：向整个网段**广播**一句话：

```
谁是 169.254.0.22？请告诉 169.254.0.21（MAC 02:fc:00:00:00:05）。
```

拥有这个 IP 的机器回答：

```
169.254.0.22 在我这里，我的 MAC 是 xx:xx:xx:xx:xx:xx。
```

问的一方把这个对应关系记进 **ARP 缓存**（也叫邻居表），之后一段时间内就不用再问了。

### 3.3 两台机器用了同一个 IP 会怎样

现在设想：同一个网段里有两台机器都声称自己是 `169.254.0.21`。

- 有人问“谁是 `169.254.0.21`”时，两台都会回答。后到的回答会覆盖先到的，于是发包方的 ARP 缓存一会儿指向 A，一会儿指向 B。
- 发给 A 的包可能被送到 B，TCP 连接莫名其妙断开。

这叫 **IP 地址冲突**，是网管最头疼的故障之一。

如果两台机器连 **MAC 地址都一样**，情况更糟：交换机会以为同一个 MAC 一会儿在这个口、一会儿在那个口，把包送来送去。

请记住这个结论，第 10 篇会用到：**在同一个二层网络里，IP 和 MAC 都必须唯一。** 而 E2B 的每个沙箱，IP 都是 `169.254.0.21`，MAC 都是 `02:FC:00:00:00:05`。

## 四、路由表：下一站交给谁

### 4.1 什么是路由

ARP 解决了“同一网段内找到对方”。如果目的地不在同一个网段呢？那就要交给一个**网关**（路由器），由它继续往下送。

每台机器都有一张**路由表**，回答一个问题：**去往某个目的地址的包，从哪块网卡发出去、交给谁？**

### 4.2 读一张路由表

Linux 上用 `ip route` 查看路由表。下面是一台宿主机上的示例：

```
$ ip route
default via 192.168.10.1 dev enp125s0f0
192.168.10.0/24 dev enp125s0f0 proto kernel scope link src 192.168.10.23
10.13.0.5 via 10.14.0.11 dev e2bv-5
10.14.0.10/31 dev e2bv-5 proto kernel scope link src 10.14.0.10
```

逐行解释：

1. `default via 192.168.10.1 dev enp125s0f0`：**默认路由**。其他规则都不匹配时，从物理网卡 `enp125s0f0` 发出，交给网关 `192.168.10.1`。去互联网的包都走这条。
2. `192.168.10.0/24 dev enp125s0f0 ... scope link`：**直连路由**。这个网段就在 `enp125s0f0` 这根线上，不用经过网关，直接用 ARP 找对方。给网卡配上地址时，内核会自动生成这种路由。
3. `10.13.0.5 via 10.14.0.11 dev e2bv-5`：去往 `10.13.0.5`（某个沙箱的 Host IP）的包，从网卡 `e2bv-5` 发出，交给 `10.14.0.11`。这是 E2B 建网时加的路由（第 12 篇）。
4. `10.14.0.10/31 dev e2bv-5 ...`：`e2bv-5` 这块网卡所在的 `/31` 小网段的直连路由。

### 4.3 最长前缀匹配

一个目的地址可能同时匹配好几条路由。比如去往 `10.13.0.5` 的包：

- 匹配 `default`，即 `0.0.0.0/0`，前缀 0 位。
- 匹配 `10.13.0.5`，即 `/32`，前缀 32 位。

规则是：**选前缀最长、也就是最具体的那条**。所以这个包会走第 3 条路由，去 `e2bv-5`，而不是走默认路由去物理网卡。

这条规则让路由表可以“粗细搭配”：一条默认路由兜底，再用一些更具体的路由处理特殊目的地。

### 4.4 “via”的含义

`via 10.14.0.11` 的意思是：**下一跳**是 `10.14.0.11`。这里要特别注意：

- 包里的**目的 IP 不变**，仍然是 `10.13.0.5`。
- 内核用 ARP 查到 `10.14.0.11` 的 MAC，把它填进以太网帧的目的 MAC，然后从 `e2bv-5` 发出去。

这就是快递比喻里的“面单收件人不变，交给下一个中转员”。

## 五、转发：帮别人送包

### 5.1 主机与路由器

一台机器收到一个包，看一眼目的 IP：

- 如果是**自己的地址**，就交给本机的程序处理。
- 如果**不是自己的**，有两种选择：
  - 普通主机的做法：丢掉。这不是给我的。
  - 路由器的做法：查路由表，**转发**出去。

Linux 两种都能当，由一个开关决定：

```
net.ipv4.ip_forward = 0   # 不转发（默认）
net.ipv4.ip_forward = 1   # 转发，充当路由器
```

### 5.2 E2B 里谁需要转发

E2B 的网络里有好几个地方需要“帮别人送包”：

- **沙箱的网络命名空间里**：从 `tap0` 进来的包（来自客户机），要从另一块网卡 `eth0` 转出去；反方向也一样。命名空间就是一台小路由器（第 6 篇）。
- **宿主机上**：沙箱发往外网的 UDP 包从 `e2bv-N` 进来，要从物理网卡转出去。

所以 `ip_forward` 必须是 1。这套环境的部署脚本 `init-client.sh` 专门处理了这件事，还踩过两个坑：

1. openEuler 自带的 `/etc/sysctl.conf` 里写死了 `net.ipv4.ip_forward=0`。执行 `sysctl -p` 时会把它压回 0。所以脚本要改这一行本身，改成 1。
2. 新建的网络命名空间，`ip_forward` 是**在创建那一刻从宿主机继承**的。如果宿主机先建好了一批沙箱网络，再把 `ip_forward` 改成 1，已经建好的那批命名空间不会跟着变。所以必须在 orchestrator 建网络池**之前**就设好。

第 21 篇会详细讲部署脚本的这些细节。现在只要记住：`ip_forward=0` 时，宿主机连沙箱里的 envd 都探测不到，因为命名空间转不了包。

## 六、读懂三条常用命令

学完上面的知识，来读一下三条最常用命令的输出。

### 6.1 `ip addr`：网卡和地址

```
$ ip addr show e2bv-5
1234: e2bv-5@if2: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP
    link/ether 6a:3c:91:0e:5d:2a brd ff:ff:ff:ff:ff:ff link-netns ns-5
    inet 10.14.0.10/31 scope global e2bv-5
```

- `1234:` 是网卡的编号。
- `e2bv-5@if2` 是网卡名，`@if2` 表示它的另一头是对端命名空间里编号为 2 的网卡。这是 veth 对的标志（第 6 篇）。
- `UP,LOWER_UP` 表示网卡已启用、线路已连通。
- `link/ether ...` 是 MAC 地址。
- `link-netns ns-5` 表示对端在命名空间 `ns-5` 里。
- `inet 10.14.0.10/31` 是 IPv4 地址和子网。

### 6.2 `ip route`：路由表

上一节已经读过了。补充一点：每个网络命名空间都有自己独立的路由表（第 6 篇）。

### 6.3 `ip neigh`：ARP 缓存

```
$ ip neigh
192.168.10.1 dev enp125s0f0 lladdr 3c:fd:fe:aa:bb:cc REACHABLE
10.14.0.11 dev e2bv-5 lladdr 9e:21:4b:7f:10:02 REACHABLE
```

每一行是一个 IP → MAC 的对应关系，`REACHABLE` 表示最近确认过还能联系上。

## 本篇小结

| 概念 | 一句话解释 |
|---|---|
| MAC 地址 | 网卡的二层地址，只在同一段线上有意义，每过一站换一次 |
| IP 地址 | 最终收件人，从起点到终点基本不变（NAT 例外） |
| 以太网帧 | 帧头（MAC）包着 IP 包，IP 包里包着 TCP/UDP |
| ARP | 广播询问“谁是这个 IP”，得到 MAC 后存进 ARP 缓存 |
| IP 冲突 | 同一网段两台机器同一 IP，ARP 混乱、连接乱断 |
| 路由表 | 回答“去往某地址的包从哪块网卡发、交给谁” |
| 默认路由 | `default` 即 `0.0.0.0/0`，兜底规则 |
| 最长前缀匹配 | 多条路由匹配时选最具体的那条 |
| `ip_forward` | 是否帮别人转发包；E2B 的命名空间和宿主机都需要它是 1 |
| 命名空间继承 | 新命名空间的 `ip_forward` 在创建时从宿主机继承，事后改宿主值不影响已建好的 |
