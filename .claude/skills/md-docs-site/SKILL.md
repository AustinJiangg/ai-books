# 把 markdown 合成单文件文档站

脚本是 `scripts/build_docs_site.py`，主题按钮在同目录的 `theme_toggle.py`，复制 skill 时要带上整个目录。
只依赖 Python 3.8+ 和 `markdown` 包（`pip install markdown`）；装了 `pygments` 时代码块自动语法高亮，没装就是单色。
公式（KaTeX）、mermaid、emoji 短码要用的库和数据都在 `scripts/vendor/` 里，生成时离线内嵌，只有文档里用到才嵌，没用到的页面不变大。
生成的 HTML 是一个文件，本地图片以 data URI 内嵌，双击就能在浏览器里打开。

适用于任何 markdown：对文件名、目录结构、标题写法都没有要求，GitHub 上常见的写法都能正确处理（见「正文支持什么」）。

## 用法

```bash
python3 scripts/build_docs_site.py --docs docs --out site.html          # 一个目录
python3 scripts/build_docs_site.py --docs README.md --out readme.html   # 单个文件
```

可选参数：

| 参数 | 作用 |
| --- | --- |
| `--title "标题"` | 站点标题，默认用第一篇的标题 |
| `--groups groups.json` | 自定义目录分组和顺序 |
| `--exclude "drafts/*"` | 跳过匹配的文件（相对 `--docs` 的 glob），可写多次 |
| `--lang en` | 界面文字用英文（目录、搜索、上一篇等），默认 `zh` |
| `--accent "#1d2125"`、`--accent-dark "#e6e9ec"` | 浅色和深色主题的强调色；默认就是墨色，不带彩色，品牌需要时再传 |
| `--sibling "../other=other.html"` | 另一套也用本脚本生成的文档：指向该目录里 md 的相对链接改成 `other.html#d<key>[-小节]`，打开对应的篇和小节；可写多次。地址相对生成的 HTML 所在位置 |

## 输入

对文件名和目录结构没有要求，下面是脚本的处理方式：

- **收集：** `--docs` 是目录时，收集其中所有 `.md`、`.markdown`，包括子目录。跳过隐藏目录、`node_modules`、`__pycache__`、`venv`、`site-packages`、`vendor` 和 `--exclude` 匹配的文件。
  - `--docs` 是单个文件时只收这一篇，页面不显示左栏和翻页，主题按钮放在右上角。
- **顺序：** 按路径自然排序（`2-a` 在 `10-b` 前）。每个目录里 `README`、`index` 排最前，根目录的文档排在子目录前。
- **编号：** 文件名以 1～3 位数字或一个大写字母加分隔符开头（`01-xxx.md`、`1_xxx.md`、`A-xxx.md`）且编号不重复时，编号显示在左栏目录里，站内地址是 `#d01`、`#dA`。日期开头（`2026-11-12-x.md`）不算编号。
- **标题：**
  - 依次取第一个一级标题（`# 标题` 或下一行是 `===` 的写法）、YAML 头的 `title`、文件名（首字母大写）。YAML 头不会显示在正文里。
  - 没有一级标题时，第一个标题（任何级别）提升为一级标题当篇名。
  - 标题以和文件名相同的编号开头时（`# 05 · 标题`、`# 附录 A · 标题`、`# 附录 A　标题`、`# 1. Setup`、`# 第 3 章 标题`、`# 第 9 篇｜标题`），去掉这个前缀，因为编号已经显示在左栏目录里。只有编号后跟着明确的分隔符（`·` `:` `：` `、` `—` `|` `｜` 等），或编号前有「附录 / Chapter」这类前缀词时才去，`# 3 ways to …` 不会被误删。`00` 编号按 `0` 匹配（`# 第 0 章`）。
  - 标题里的行内代码（`` # 从一行 `curl` 说起 ``）在正文标题里保留代码样式，在左栏和标签页标题里显示为纯文字。
- **目录分组：** 默认按顶层子目录分组，组名是目录名（去掉编号前缀，`-`、`_` 换成空格，首字母大写）。

`groups.json` 里每篇写文件名开头的编号或相对 `--docs` 的路径，组名为空字符串的组不显示标题。没有列出的文档放进「其他」组：

```json
[["", ["00"]], ["指南", ["01", "guide/setup.md"]], ["接口", ["api/ref.md"]]]
```

## 正文支持什么

- **图片：** `![说明](路径)` 和 `<img src="路径">`，路径相对当前文档，支持 svg、png、jpg、gif、webp、avif。
  - 单独占一行的图成为带说明的 figure；在句子里的图保持行内。
  - 文件名是 `NN-k-名字.svg` 时，说明前加「图 NN-k」。
  - `http(s)` 外链图保留原样，所以离线时看不到。
  - 找不到的图在正文显示「缺图」，并在生成时输出警告。
  - 引用式图片 `![说明][id]` 的定义行 `[id]: 图.png` 也会内嵌。
  - 宽度不到 760px 的 SVG 和所有位图按原尺寸居中，不拉伸；更宽的 SVG 铺满正文宽度。
- **链接：** 相对链接指向站内某一篇时变成站内跳转，`#小节` 能跳到对应标题。下面几种写法都认：
  - `[文字](x.md)`、`[文字](x.md#小节)`、`[文字](#小节)`；
  - 省略扩展名 `[文字](guide/usage)`，指向目录 `[文字](api/)`（取目录里的 `README` / `index`，没有就取第一篇）；
  - 引用式 `[文字][id]` 加定义行 `[id]: x.md#小节`；
  - HTML 写法 `<a href="x.md">`。
- **裸网址：** 正文里的 `https://…` 自动变成链接（代码里的不变）。
- **语法：** 表格、代码块、引用、列表、`~~删除线~~`、任务列表 `- [x]`、脚注 `[^1]`、定义列表（`术语` 下一行 `: 解释`）、HTML 块里的 markdown（`<div markdown="1">`）。
- **GitHub 提示块：** `> [!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]` 显示成带标题、左侧色条的提示框。这是全页唯一带彩色的地方，因为颜色本身表示提示的级别。
- **GitHub 写法：**
  - 2 格、3 格、4 格缩进和 tab 混用的嵌套列表都按嵌套关系换算；列表前没有空行、列表里的代码块也能处理。
  - 两段引用之间只隔一个空行时，仍然是两段（python-markdown 默认会合成一段）。
- **语法高亮：** 装了 pygments 时，带语言的代码块按语言上色（包括列表里的代码块），浅色主题用 `default` 配色，深色主题用 `github-dark` 配色；没写语言的不猜。
- **公式：** `$…$` 行内公式，`$$…$$` 和 ` ```math ` 独立公式，用 KaTeX 渲染（打开页面时在浏览器里渲染，离线可用）。
  - 判定规则同 GitHub：`$` 后不能紧跟空格，结尾 `$` 前不能是空格、后面不能紧跟数字或字母，所以 `$5 and $10` 这样的金额不会被误认；`\$` 是普通的美元符号。
  - 公式里的 `_`、`*` 不会被当成强调。
  - 内嵌约 640 KB（含字体）。
- **mermaid：** ` ```mermaid ` 代码块渲染成图，跟随深浅色主题，切换主题时重画；点图可以全屏放大。只渲染当前打开的那一篇（隐藏的篇量不出尺寸）。内嵌约 3.3 MB。
- **emoji 短码：** `:rocket:`、`:white_check_mark:` 等 GitHub 的 1913 个短码换成 emoji 字符；代码里的、`12:30:45` 这样的时间、`a:b:c` 这样夹在字母中间的不动。

已知限制：

- 指向 md 和图片以外的相对链接（比如 `../src/a.py`）、指向不存在文件的链接，生成时会按「文档 → 地址」逐条列出来，页面里保留原地址。
  - 指向 `--docs` 之外另一套文档的 md 链接，用 `--sibling` 告诉脚本那套文档生成在哪个 HTML 里，就会改成跳到那个页面的对应篇和小节；对方的站内 key 按同样的规则（编号或 `p<序号>`）算，所以那套文档也要用本脚本、不带 `--exclude` 生成。
- 用了 mermaid 的站点会大 3.3 MB；在意体积时，把图先画成 SVG，再用 `![说明](图.svg)` 引用。

## 排版要点（改样式时保持这些）

风格目标是「好读、安静」：正文、图、表格左右对齐成一栏，居中；装饰只用留白和细线，整页不带彩色（彩色留给配图里的数据）。左栏顶部只有站点标题和主题按钮，不放副标题、版本、篇数、装饰色块这类东西。

- **三栏布局：**
  - 左侧 288px 目录（sticky），中间正文，右侧 248px「本篇小节」。
  - 本篇小节只在宽度 ≥ 1280px、而且这篇至少有两个二级标题时显示，用 h2/h3 生成，滚动时高亮当前小节。
  - 本篇小节比屏幕高时，右栏要跟着正文走：当前小节跑出右栏可见范围，右栏自己平滑滚过去，让它停在上三分之一处。鼠标正在右栏里时不自动滚，免得和用户抢。这是文档站的通行做法（MDN、Docusaurus 都这样），不能只高亮、不滚动。
  - 宽度 ≤ 860px 时左栏变成抽屉：顶栏有「目录」按钮，点遮罩关闭；右栏不显示。
- **阅读宽度：** 正文一栏最宽 960px，居中，字号 16px、行高 1.85。配图、表格、代码块和正文同宽，左右边缘对齐，不向两侧伸出：正文比图窄时版面两边参差，不好看。
- **篇首：**
  - 直接是 36px 的标题，标题上方不放编号、分组这类小字（编号在左栏目录里已经有了）。
  - 标题后紧跟的引用块（如「本章回答 / 前置」）显示成浅灰底圆角的提要框。
- **标题：** 不用分隔线，层级靠字号和上方留白（h2 上方 72px）。
- **元素：**
  - 代码块和行内代码都是浅底细边圆角；表格外有一圈细边圆角，表头浅底，行悬停变色。
  - 数字统一用等宽数字（`tabular-nums`）。
  - 配图直接放在页面上，不套卡片、边框、阴影和内边距，只给图片 10px 圆角。
  - 图注在图下方居中，13.5px，整行同一个颜色（`--ink-2`）。编号写成「图 4-5」，去掉文件名里的前导零，比说明稍重（600），和说明之间隔一个字宽。
    - 不要把编号做成深色粗体、说明做成浅灰：两种颜色、两种字重挤在一行，看起来像两段不相干的字。
    - 理由：图本身就是白底且自带留白。浅色主题下再套一层卡片，就是框里套框；深色主题下卡片底色和图的白底稍有不同，就像多了一圈灰边。深色主题里图的白底本身就是清楚的边界，不需要再加东西。
    - 透明底的图在深色主题下会看不清，所以图片本身垫白底（`figure.paper img{background:#fff}`）。这对白底的图没有影响，也不是卡片。
  - 窄屏时 SVG 图可以横向滚动。
- **字体：** 中文字体回退链是 PingFang SC → Hiragino Sans GB → Noto Sans CJK SC → Source Han Sans SC → 微软雅黑；等宽字体用 SF Mono / JetBrains Mono。
- **配色：** 颜色全部是 `:root` 上的 CSS 变量，深色主题在 `prefers-color-scheme: dark` 和 `[data-theme=dark]` 下各定义一次。强调色默认是墨色（浅色 `#1d2125`、深色 `#e6e9ec`），浅底 `--accent-soft` 由它和背景色混出来；当前篇、本篇小节高亮、进度条都用它，所以整页是黑白灰。
- **全书搜索：**
  - 左栏顶部有搜索框，按 `/` 聚焦，`Esc` 清空，回车打开第一篇命中的文档。
  - 目录只留命中的篇，每篇显示命中次数。
  - 当前篇里的命中用 CSS Custom Highlight API 高亮，不改 DOM；浏览器不支持时只是不高亮。
  - 从搜索结果点进一篇时，页面滚到第一处命中。
- **阅读辅助：**
  - 页面顶部 2px 的阅读进度条。
  - 键盘 ← / → 切换上一篇和下一篇。
  - 浏览器标签页标题跟随当前篇。
  - 每篇末尾有「上一篇 / 下一篇」：两个细边小框，只写篇名，不带编号，宽度随文字，分别靠左、靠右；不要做成各占半栏的大卡片。
- **看大图：** 配图上的鼠标指针是放大镜，点图打开全屏查看，初始适合屏幕。
  - 滚轮以指针为中心缩放，拖动平移，双击在适合屏幕和 2.5 倍之间切换，手机上双指缩放。
  - 底栏有图号和说明、缩小 / 百分比 / 放大、「适合」、关闭。
  - 快捷键：`+` / `-` / `0` 缩放和复位，`Esc` 或点空白处关闭；打开时 ← / → 不翻篇，焦点留在查看器里。
- **主题按钮：** 只放图标，不写「深色/浅色」这类文字。
  - 按钮显示点击后会切到的主题：浅色时是月亮，深色时是太阳。图标是内联 SVG，不用 emoji。
  - 尺寸 36×36px，有悬停和键盘焦点样式。
  - 名称固定为「深色模式」，状态由 `aria-pressed` 表达；悬停提示写「切换到…模式」。
  - 记住用户的选择；没有选择时跟随系统，系统切换时图标同步。
  - 主题在 `<head>` 里同步设置，避免页面先闪一下错的配色。
  - 其他单文件 HTML 要同样的按钮时，导入 `theme_toggle.py`，用法见它的文件头，不要另写一份。
- **脚本结构：** 样式和脚本分别写在 `build_docs_site.py` 里的 `CSS`、`JS` 两个普通字符串里，不在 f-string 里，大括号不用写两遍。

## 交付前检查

改了 `build_docs_site.py` 之后，除了目标文档，还要用 `tests/sample/` 跑一遍。这是一套刻意写得五花八门的英文样例：下划线标题、没有一级标题、目录链接、引用式链接、脚注、提示块、混合缩进列表、透明 SVG，以及 `guide/advanced.md` 里的公式、mermaid、emoji、列表里的代码块。目的是确认改动对任意 markdown 都成立，而不只是对手头这一套：

```bash
python3 scripts/build_docs_site.py --docs tests/sample --out /tmp/sample.html --lang en
python3 scripts/build_docs_site.py --docs tests/sample/guide/usage.md --out /tmp/single.html --lang en
```

样例里故意留了 2 个断链（`./nope.md`、`../../src/main.py`），输出里应该正好是这 2 条，warnings 为 0。打开 `Advanced syntax` 那篇，公式、流程图、高亮都应该渲染出来，深色主题下也看得清。

脚本结束时会输出下面几项，都应为 0，不为 0 就逐条处理：

- `unresolved local links`：没能转成站内跳转的相对链接。
- `raw img refs`：没有转换的图片语法。
- `warnings`：缺图、不支持的图片格式、`groups.json` 里写错的条目。

再用 Playwright（或 headless Chrome 的 `--screenshot`）打开生成的文件，分别看 1440px 宽的浅色和深色视图、1100px 宽（没有右栏）的视图，以及 390px 宽的手机视图：

- `document.documentElement.scrollWidth` 不超过视口宽度。
- 控制台没有报错。
- 图片在正文里完整显示，没有被裁掉；目录高亮跟随当前篇；宽屏时右栏小节随滚动高亮。
- 搜索一个词，目录只剩命中的篇并显示次数，点进去命中处高亮；手机上「目录」按钮能打开和关闭抽屉。
- 点一张图能全屏打开，滚轮缩放、拖动正常，`Esc` 能关闭；深色主题下图外没有多一圈灰框。
- 点主题按钮后配色和图标都切换，刷新后选择还在；键盘 Tab 能聚焦到按钮，空格或回车能切换。
